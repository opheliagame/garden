iOS プロファイリング

Xcode Instruments: Energy Log

Xcode Instruments: Energy Log

  • iOS はまず Energy Log
  • 絶対値より、同じ端末で前後比較
  • idle で下がるか、熱状態も見る

算出メカニズム

  • カーネル評価値: CPU/GPU/ネットワーク/カメラ等の使用量をiOSカーネルが総合評価
  • 20段階エネルギーインパクト: 0 (Very Low) 〜 20 (Very High) の相対指標
  • Thermal State 連携: Nominal (正常) / Fair / Serious / Critical (過熱スロットリング) を監視

計測のやり方とチェックポイント

  • 実機を Wi-Fi デバッグ接続し Xcode Instruments の Energy Log を起動
  • アプリ画面の無操作時にスコアが 0〜1 に即座に下がるか判定
  • スクロールやアニメーション中に 15 以上 のスパイクが持続しないか確認

Batterystats / Historian / Perfetto

Batterystats / Historian / Perfetto

メインIsolate（CPU）の短時間占有

重い計算が UI と同じ main isolate で走ると、CPU が一気に上がって熱も battery もきつくなります。

対策: Isolate.run() や compute() に逃がす。

例: 大きい JSON の jsonDecode や、履歴DBの暗号化。

画面外アニメーションの無駄な再描画

Opacity: 0 でも Ticker は止まらないので、見えていなくても GPU 仕事が続くことがあります。

対策: 非表示時は stop()、または lifecycle に合わせて pause / dispose。

例: 別タブに行った後も、裏側で loading や slideshow が回り続ける時。

細かすぎる通信と Radio Tail Time

数バイトでも通信チップは高電力モードに起きて、しばらくそのまま残ります。小分け通信は地味に高いです。

対策: polling を減らす。Push、WebSocket、batch 送信を使う。

例: Timer.periodic で 1〜2秒ごとに新着チェックを投げ続ける時。

実装・設計指針

今日の持ち帰り: 4つの設計原則

今日の持ち帰り: 4つの設計原則

  • ここからは LT のまとめパート
  • 見えない時は止める
  • repaint の範囲を小さくする
  • 重い effect は状況で弱める

1. ライフサイクル連動

画面非表示時・バックグラウンド移行時は即座にアニメーションとTimerを完全停止。

2. 描画境界の適切な隔離

変化頻度の高いウィジェットに RepaintBoundary を付与し、静的UIの再描画を防止。

3. 状況に応じたエフェクト調整

低電力モード時やスクロール中は、重い装飾・ぼかしを自動でフラット表示に切替。

4. AIアシスタントへの指針共有

LLMにコード生成させる際、安易に Opacity や BackdropFilter を書かせないプロンプト規約を策定。
