エネルギーの基本

  • CPU: アプリの処理や画面の準備
  • GPU: 画像の合成や効果の計算
  • 処理や描画が続くと、使うエネルギーも増えることがある
  • 画面が滑らかかどうかだけでは、使用の量は分からない

まず、CPUやGPUの動きと、電気の使い方を簡単に見てみます。

CPUやGPUの中には、たくさんの小さな電子スイッチがあります。計算するときは、このスイッチを切り替えます。計算が増えたり、速く動かしたりすると、電気を多く使うことがあります。

画面が変わらず、することがなければ、CPUは休んで電気を節約できます。ところが、必要のない処理や画面の描き直しが何度も続くと、CPUは休みにくくなります。GPUも、画面を描き直すたびに働きます。

実際に電気をどれくらい使うかは、電流を測る機器で調べられます。OSのプロファイラを使うと、CPUやGPUの動きや、エネルギーの変化も確認できます。比べるときは、同じ端末で同じ操作をすることが大切です。

ただし、CPUやGPUの動きと電気の使用量が一緒に増えても、それだけで原因が分かったとは言えません。今日は、測定結果を手がかりに考えていきます。

この考え方を、BackdropFilterの一つの例に当てはめます。

BackdropFilterの裏側

まず、BackdropFilterより後ろにあるwidgetが先に描画されます。

BackdropFilterはImageFilterをRenderObjectとLayer treeに渡します。

RasterizerはClipRectなどで制限された範囲の、すでに描かれた背景を使ってフィルター結果を作ります。

その結果をblendModeに従って合成し、最後にBackdropFilterのchildを前景として描画します。

childの範囲と、フィルターが読む背景の範囲は同じとは限りません。範囲を制限するClipが重要です。

背景が変わればフィルター結果の更新が必要になることがあり、範囲や更新頻度が描画負荷に影響します。

BackdropFilterとエネルギー

  • 背景をコピーし、ぼかして重ねる
  • 背景が更新されると、もう一度処理することがある
  • 範囲やフィルター数が大きいほど、描画の仕事が増える
  • CPU・GPUの仕事が続くと、電力も増えることがある

BackdropFilterは、ガラスの見た目だけではなく、後ろにある画面を使って効果を作る処理です。

まず、すでに描かれた背景を必要な範囲で取り込みます。その背景をぼかして画面に重ね、最後に子どものwidgetをその上に描きます。

背景が変わると、ぼかしの結果も更新する必要が出ることがあります。範囲が広い、フィルターが多い、更新が頻繁、といった場合は、コピーやぼかし、合成の仕事が増えます。

その仕事にはGPUの描画処理やメモリの読み書きが必要です。CPUもフレームの準備をします。仕事が長く続けば、端末が使うエネルギーも増える可能性があります。

@Test

    packageName = "com.example.app",
    metrics = listOf(FrameTimingMetric()),
    iterations = 5,
) {
    startActivityAndWait()
    device.findObject(By.res("home_list"))
        .fling(Direction.DOWN)
}
